- IMPORTANT: When creating markdown documents, always add a blank line before bullet lists (lines starting with `-`) and numbered lists (lines starting with `1.`, `2.`, etc.). This is required for Marked2 (https://marked2app.com/) to render lists properly. Without the blank line, lists render as plain text instead of formatted lists.
- When creating numbered lists in markdown, always use `1.` as the prefix for every item. Markdown renderers auto-number them, and this makes reordering easier.
- When creating analysis, investigation, finding, or debugging documents (typically saved under `tmp/`), version them with a two-part pattern. (1) At the very top of the file, before the title, place a minimal summary table with columns `Version` and `Timestamp` and exactly one row holding the latest values. (2) At the very bottom of the file, in a `## Version History` section, place the full history table with columns `Version`, `Updated`, `Change`; insert each new row at the TOP of that table (newest first) with a one-line `Change` summary. Use SemVer starting at `0.1.0`; bump patch (`0.1.0` -> `0.1.1`) for typos/minor fixes, minor (`0.1.0` -> `0.2.0`) for new findings, sections, or corrections to procedures, major (`0.x.y` -> `1.0.0`, then `2.0.0`, ...) for retractions of earlier conclusions or substantial rewrites. Timestamp format is `YYYY-MM-DD HH:MM <tz>` (e.g. `2026-04-23 16:30 PDT`) - granularity to minutes only, never seconds. The top-row `Timestamp` and bottom-row `Updated` values must match for the latest version. This applies even on the first draft - create both tables with the initial `0.1.0` row. Does not apply to commit messages, PR descriptions, code comments, or documents that live outside `tmp/` (e.g., README, DOMAIN.md, documentation/).
